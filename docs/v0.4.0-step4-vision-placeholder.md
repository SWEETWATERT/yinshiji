# v0.4.0-step4 视觉识别占位层说明

## 当前识别链路

用户在小程序里拍照或上传餐食图片后，当前链路为：

1. 拍照/上传图片
2. 调用 `analyzeMeal`
3. `analyzeMeal` 先调用 `services/visionAnalyze.js` 的视觉识别占位层
4. 占位层返回稳定的 `visionResult`
5. 当前主识别仍走 `note` 备注关键词 + `food_items` 食物库匹配 fallback
6. 用户在分析页确认结果
7. 调用 `saveMealRecord` 保存餐食记录

## 当前不是图片 AI

本步骤不接入真实外部 AI，也不会解析图片内容。

当前图片可以上传并进入识别流程，但图片内容尚未被视觉模型分析。`visionResult.modelProvider` 固定为 `placeholder`，用于为后续真实视觉识别预留稳定接口。

## 返回结构

`analyzeMeal` 会继续保留原有字段：

- `detectedFoods`
- `total`
- `warnings`
- `aiAdvice`
- `candidates`
- `recognitionSource`
- `modelProvider`
- `modelVersion`
- `confidence`
- `needReview`

同时新增：

- `visionResult`

当前 `visionResult` 示例：

```json
{
  "ok": true,
  "recognitionSource": "vision_placeholder",
  "modelProvider": "placeholder",
  "modelVersion": "v0.4.0-step4",
  "confidence": 0,
  "detectedFoods": [],
  "candidates": [],
  "warnings": [
    "当前版本暂未接入真实视觉 AI，图片内容不会被模型解析，将继续使用备注关键词和食物库匹配。"
  ]
}
```

## 后续 step5 可接入方向

`services/visionAnalyze.js` 后续可替换为真实服务实现：

- Tencent Cloud Vision
- OpenAI Vision
- Doubao
- Qwen

真实模型返回后，可以先进入 `candidates`，再由食物库二次校准营养字段，最后让用户确认。

## 风险

- 真实图片识别会产生模型调用成本。
- 图片识别可能不准确，尤其是混合菜、遮挡、汤汁、外卖包装场景。
- 热量估算仍需要用户确认份量，不能直接当作医学判断。
- 图片属于用户隐私数据，后续接真实模型前需要明确隐私说明、数据用途和删除机制。

## 验收方式

1. 不填备注，只上传图片：`analyzeMeal` 不应崩溃，返回结果里应包含 `visionResult`。
2. 填写 `牛肉100克`：仍应通过关键词 + `food_items` 匹配识别牛肉。
3. 填写 `白粥200克`：仍应通过关键词 + `food_items` 匹配识别白粥。
4. 返回结果里应包含 `visionResult`。
5. 当前 `visionResult.modelProvider` 应为 `placeholder`。
