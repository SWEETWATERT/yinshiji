# v0.2 Admin Review Plan

## 1. v0.2 目标

v0.2 的目标是在不破坏 v0.1 主链路的前提下，补齐后台管理和人工复核的最小闭环。当前小程序已经跑通微信登录、资料填写、餐食分析、保存、日记、首页汇总、周报和我的页资料读取。v0.2 只在此基础上增加管理员可进入的后台模块，用于查看数据、处理低置信度识别、维护食物库和处理用户反馈。

技术栈保持不变：继续使用微信小程序原生页面、微信云开发云函数和云数据库，不引入新的后台框架或外部管理系统。

## 2. 后台管理页面结构

后台页面不加入底部 tabBar，入口暂时隐藏在「我的」页，仅 `user.isAdmin === true` 时展示。

- `pages/admin/index`：后台首页和菜单，展示数据看板入口和管理模块入口。
- `pages/admin/users`：用户管理，后续展示用户资料、目标、记录状态。
- `pages/admin/meals`：餐食记录，后续按日期、餐次、用户筛选记录。
- `pages/admin/reviews`：AI 复核，后续处理 `review_tasks` 中的待复核任务。
- `pages/admin/foods`：食物库，后续维护 `food_items`、别名和每 100g 营养数据。
- `pages/admin/feedback`：用户反馈，后续处理 `user_feedback`。
- `pages/admin/config`：配置管理，后续维护 `app_config`。

本阶段只创建页面骨架和空状态，不接复杂列表和编辑表单。

## 3. adminApi action 设计

当前 `cloudfunctions/adminApi` 已有以下基础 action：

- `whoami`：返回当前 openid 是否为管理员。
- `bootstrapAdmin`：通过 `ADMIN_SETUP_KEY` 初始化当前用户为 owner。
- `dashboard`：统计用户、餐食、今日餐食、食物库、分析日志、待复核、未关闭反馈数量。
- `listUsers`：分页查询 `users`。
- `listMeals`：分页查询 `meal_records`，支持 openid、date、mealType 过滤。
- `listFoodItems`：分页查询 `food_items`，支持 category、keyword 过滤。
- `upsertFoodItem`：新增或更新食物库条目。
- `listReviewTasks`：分页查询 `review_tasks`，支持 status 过滤。
- `resolveReviewTask`：处理复核任务，写入复核人、状态、修正内容和备注。
- `listFeedback`：分页查询 `user_feedback`，支持 status、type 过滤。
- `updateFeedbackStatus`：更新反馈处理状态和管理员备注。
- `getAppConfig`：读取 `app_config`。
- `setAppConfig`：写入 `app_config`。

后续页面接入时，所有管理 action 都走 `adminApi`，前端不直接用数据库读取后台数据。

## 4. 管理员权限方案

管理员权限只在云端判断，不把管理员 openid 写死在前端。

权限来源优先级：

1. 云函数环境变量 `ADMIN_OPENIDS`：逗号分隔的 openid 白名单，适合正式管理员。
2. 数据库集合 `admin_users`：保存 `_openid`、`role`、`status`、创建时间和更新时间。
3. `bootstrapAdmin`：仅在配置了 `ADMIN_SETUP_KEY` 后，用于首次初始化管理员。

原则：

- `whoami` 可被普通用户调用，只返回当前用户是否管理员、角色和提示信息。
- 除 `whoami`、`bootstrapAdmin` 外，所有后台 action 必须先执行管理员权限检查。
- 普通用户不能通过前端入口看到后台，也不能通过云函数读取后台数据。
- `profile` 页只在 `user.isAdmin === true` 时展示后台入口；未设置或 false 都不展示。

## 5. 数据看板字段

后台首页后续通过 `adminApi.dashboard` 展示以下卡片：

- 用户总数：`users.count()`
- 餐食记录总数：`meal_records.count()`
- 今日餐食数：`meal_records.where({ date: today }).count()`
- 食物库条目数：`food_items.count()`
- AI 分析日志数：`analysis_logs.count()`
- 待复核任务数：`review_tasks.where({ status: 'pending' }).count()`
- 未关闭反馈数：`user_feedback.where({ status != 'closed' }).count()`

本轮后台骨架先显示菜单，不拉取看板数据。

## 6. AI 复核任务流程

复核任务来自两个方向：

- `analyzeMeal`：识别为空、识别低置信度、需要用户确认份量时写入 `review_tasks`。
- `submitFeedback`：用户反馈识别错误、营养错误、份量错误、图片不清晰时写入 `user_feedback`，必要时同步生成 `review_tasks`。

后续复核流程：

1. 管理员进入 `pages/admin/reviews`。
2. 调用 `adminApi.listReviewTasks({ status: 'pending' })`。
3. 查看图片、备注、识别食物、估算热量、用户反馈。
4. 管理员确认、修正或忽略。
5. 调用 `adminApi.resolveReviewTask` 写入 `status`、`reviewerOpenid`、`correctedFoods`、`resolutionNote`、`resolvedAt`。
6. 后续可把修正结果沉淀为食物库别名或识别规则。

## 7. 食物库编辑流程

食物库仍使用 `food_items` 集合，核心字段包括：

- `foodId`
- `nameCn`
- `category`
- `aliases`
- `kcalPer100g`
- `proteinPer100g`
- `carbsPer100g`
- `fatPer100g`
- `fiberPer100g`
- `icon`
- `defaultWeightG`
- `verified`
- `dataSource`
- `dataSourceNote`

后续编辑流程：

1. 管理员进入 `pages/admin/foods`。
2. 调用 `adminApi.listFoodItems` 查看和搜索食物。
3. 新增或编辑食物条目。
4. 保存时调用 `adminApi.upsertFoodItem`。
5. 新增别名后，`analyzeMeal` 可通过 `food_items.nameCn` 和 `aliases` 命中更多用户备注。

正式上线前建议用权威食物成分表或品牌营养标签复核高频食物数据。

## 8. 用户反馈处理流程

用户反馈进入 `user_feedback`，并可关联 `mealRecordId`、`analysisId` 和 `reviewTaskId`。

后续流程：

1. 管理员进入 `pages/admin/feedback`。
2. 调用 `adminApi.listFeedback({ status })` 查看反馈。
3. 对识别错误、营养错误、份量错误等反馈，跳转到复核任务或创建复核动作。
4. 处理后调用 `adminApi.updateFeedbackStatus` 写入 `status`、`adminOpenid`、`adminNote`、`updatedAt`。
5. 对高频问题沉淀为食物库别名、识别规则或产品文案优化。

## 9. 不做什么

v0.2 第一阶段不做以下事项：

- 不改 v0.1 的餐食分析、保存、日记、首页、周报主链路。
- 不删除 mock 文件。
- 不删除 `debugInput`。
- 不接真实付费视觉 AI。
- 不做复杂后台 UI、批量编辑、导出、图表系统。
- 不改数据库集合名。
- 不改底部 tabBar。
- 不把管理员 openid 写死在前端。
- 不做会员系统、医生诊断或医疗判断功能。

## 10. 分阶段开发顺序

1. 后台骨架：注册后台页面、隐藏入口、后台菜单和空状态。
2. 权限确认：完善 `adminApi.whoami` 返回 openid、isAdmin、roles、message。
3. 数据看板：`pages/admin/index` 接入 `adminApi.dashboard`。
4. 复核列表：`pages/admin/reviews` 接入 `listReviewTasks` 和 `resolveReviewTask`。
5. 食物库列表：`pages/admin/foods` 接入 `listFoodItems`。
6. 食物库编辑：接入 `upsertFoodItem`，支持别名和营养字段维护。
7. 用户反馈：接入 `listFeedback` 和 `updateFeedbackStatus`。
8. 用户与餐食记录：接入 `listUsers`、`listMeals`，用于排查数据和运营观察。
9. 配置管理：接入 `getAppConfig`、`setAppConfig`，维护开关、提示文案和阈值。
10. 上线前复核：补齐隐私合规文案，评估是否移除测试字段 `debugInput`。
